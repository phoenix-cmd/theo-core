## 1. Abstract

THEO v0.4.1 is a deterministic symbolic cognition platform. It executes a
9-stage cognitive cycle over a structured state of beliefs, thoughts, memories,
and goals; records each cycle as a fully auditable GoldenTrace; and provides
executable governance (ADRs, conformance suites, and a benchmark CLI) that
enforces the cognitive Canon. The version's defining property is **determinism
by contract**: identical inputs and identical pre-cycle state produce
byte-identical cognitive fingerprints and state transitions, verified at replay
time through state-hash invariants.

THEO's purpose is to serve as a *control condition* for cognitive research —
a reference implementation whose behavior is trustworthy enough that later
capabilities (neural proposal generation, retrieval augmentation, learned rule
ranking, neuro-symbolic reasoning) can be measured against it.

## 2. Scope

### 2.1 In Scope

- **Symbolic cognitive runtime**: the 9-stage canonical pipeline
  (ADR-0027) with belief/thought/goal/memory models.
- **Replay engine**: faithful re-execution of a recorded cycle from restored
  pre-cycle state, with state-hash and fingerprint verification.
- **Cognitive benchmark corpus**: 35 cases across 6 domains, evaluated by a
  deterministic harness and the `theo benchmark run` CLI.
- **Executable governance**: ADR index, ADR-to-symbol import mapping,
  Canon conformance suites, deterministic property suites.
- **Legacy compatibility path**: the v0.2 12-stage `CognitiveEngine`, available
  only via `theo chat --engine legacy`, and explicitly *outside* the v0.4.1
  runtime contract.

### 2.2 Out of Scope

- **Neural proposal generation** — hypothesis production is rule-based and
  deterministic; no learned or stochastic components.
- **Learning / parameter adaptation** — the LEARNING stage records structure;
  no weights, gradients, or models are trained.
- **Hybrid / neuro-symbolic reasoning** — no neural components exist in the
  canonical runtime.
- **Timing fidelity** — wall-clock durations are not part of the determinism
  contract (see §4).

## 3. Architecture Overview

### 3.1 Canonical Runtime

The canonical runtime executes the 9-stage cognitive cycle
(`CycleStage` in `symbolic/scheduler/models.py`):

1. **PERCEPTION** — input enters cognition as evidence; a percept belief is
   derived (`belief://percept/<sha256(input)[:8]>`). Per ADR-0026, perception
   never generates a new `BeliefSource`.
2. **ACTIVATION** — memories and beliefs relevant to the current context are
   activated.
3. **REVISION** — the conflict resolver runs *before* hypothesis generation;
   seeded contradictions are resolved deterministically (equal-confidence ties
   keep the lower belief id).
4. **INFERENCE** — forward rules fire over active beliefs; fired rules and
   derived beliefs are recorded.
5. **HYPOTHESIS** — candidate hypotheses are generated per matching belief,
   plus one perceptual candidate; sorted by `(-score, id.value)`.
6. **CONFLICT_RESOLUTION** — competing hypotheses are resolved; the active
   hypothesis set must be consistent (Canon Law 6 — no premature collapse,
   ambiguity persists while uncertainty persists).
7. **DECISION** — a `DecisionRecord` is produced: intent derived from a
   referenced Goal, plus an `ActionSpec`.
8. **REALIZATION** — the decision is rendered through the boundary
   `ResponseRenderer`; no language is generated *inside* cognition.
9. **LEARNING** — the cycle's structure is committed to memory.

The runtime is composed via `composition/bootstrap.py`'s canonical
`engine_factory`, which wires the scheduler, inference engine, hypothesis
engine, conflict resolver, and memory repository.

### 3.2 Cognitive State

Cognitive state is structured: beliefs (proposition, confidence, uncertainty,
evidence, provenance), thoughts (immutable temporary objects), goals, and
memories. `BeliefSource` is closed at **MEMORY / KNOWLEDGE / INFERENCE**
(ADR-0026); perception enters as *evidence*.

### 3.3 Executable Governance

- **Canon** (`CANON.md`, Edition C1) — normative laws, incl. Invariant 2
  (determinism) and Invariant 8.
- **ADRs** (`adr/`, ADR-0019…ADR-0027) — test-enforced index completeness,
  sequential numbering, status validity, and ADR-to-symbol import mapping
  (`tests/adr/`).
- **Conformance suites** — belief laws, Canon Law 6, canonical-vs-legacy
  isolation.

## 4. Determinism Contract

> **Determinism is defined over cognitive state transitions, not over
> serialized artifacts or wall-clock metadata.**

- A cognitive cycle's observable output is the **cognitive fingerprint**
  (`theo_golden_fingerprint`), computed over the decision and structural
  trace.
- A cycle's state effect is captured by **state hashes**:
  `theo_state_hash_before` = SHA-256 over a canonical projection of the
  pre-cycle state; `theo_state_hash_after` = same for the post-cycle state.
- The canonical projection strips **volatile execution metadata**:
  `last_verified`, `created_at`, and the derived per-graph `checksum`.
  These are metadata *about* execution, not cognition. Re-execution can never
  reproduce wall-clock timestamps byte-identically, so determinism is defined
  over the cognitive payload after stripping them.
- With no `ComputeBudget`, `SchedulerTrace.total_time_ms` is `None` — the
  trace itself is fully deterministic.
- **Cross-process determinism** holds: independent subprocesses produce
  byte-identical sha256 fingerprints.

Invariant: `deterministic(runtime, cycle) ⟺ hash(S(t)) → execute → hash(S(t+1))`
is reproducible for identical inputs and identical pre-cycle state.

## 5. Replay Contract

Replay treats THEO as a deterministic state machine, not merely a
response generator:

1. The recorded trace stores the **pre-cycle state** (`theo_pre_cycle_state`),
   the **pre-state hash** (`theo_state_hash_before`), the **post-state hash**
   (`theo_state_hash_after`), and the **golden fingerprint**
   (`theo_golden_fingerprint`).
2. Replay restores the recorded pre-cycle state into a **fresh runtime** —
   it never re-executes against a live runtime's already-advanced state.
3. The fresh runtime executes the cycle from that restored state.
4. Replay verifies both state-hash invariants:
   - `pre_state_hash_replay == theo_state_hash_before` (replay started from
     the same state)
   - `post_state_hash_replay == theo_state_hash_after` (replay produced the
     same state transition)
5. Replay compares the replayed fingerprint against the golden fingerprint.
6. **A hash mismatch forces failure**: `matched=False` and `variance=1.0`.
   Divergence is authoritative, not merely diagnostic. If a trace records
   hashes but the engine cannot compute them, replay raises `RuntimeError`.

The `ReplayEngine` is generalized over a `ReplayableEngine` protocol
satisfied by both the canonical runtime and the legacy engine; the v0.4.1
contract covers the canonical runtime.

## 6. Benchmark Methodology

- **Corpus**: 35 cases across 6 domains — ambiguity (5), causal_reasoning (8),
  commonsense (5), contradiction (7), taxonomy (5), uncertainty (5).
  Each domain has ≥5 cases, enforced by a corpus test.
- **Domains target distinct failure modes**:
  - taxonomy — classification/ordering structure
  - causal_reasoning — rule firing and negative controls (rules must NOT fire)
  - contradiction — conflict resolution and tie-breaking
  - planning — multi-step goal pursuit
  - uncertainty — low-confidence signal handling
  - ambiguity — remaining uncertain when uncertainty exists (Canon Law 6)
- **GoldenTrace**: complete per-cycle structural trace (retrieved memories,
  fired rules, derived beliefs, generated hypotheses, resolved conflicts,
  thought DAG). Cases carry metadata keys: `theo_golden_fingerprint`,
  `theo_pre_cycle_state`, `theo_state_hash_before`, `theo_state_hash_after`.
- **Harness** (`evaluation/harness.py`): deterministic comparison of expected
  vs actual Belief Graphs, Decisions, and GoldenTraces — asserting only
  explicitly specified fields.
- **CLI** (`theo benchmark run`): executable governance with domain/case
  filters; exit code 1 on failure.
- **Golden-trace pinning**: expectations are generated by running the
  deterministic pipeline first, then pinning the observed traces; per-case
  tests exist for the new ambiguity and negative-control cases.

## 8. Known Limitations

- **Legacy engine**: the v0.2 `CognitiveEngine` is maintained for
  compatibility but is outside the v0.4.1 contract.
- **Determinism scope**: deterministic over cognitive state, not over
  wall-clock timing or serialization metadata (§4).
