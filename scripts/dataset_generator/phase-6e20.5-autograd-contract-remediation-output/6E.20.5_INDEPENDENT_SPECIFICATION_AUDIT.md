## B. Design Correctness

- **Option A rejection is evidence-based.** The caller map (§2) shows `forward_margin` is consumed by `compute_decision_margin_and_metrics` (NumPy scalar path, L519/535) and by Stage 8 via `margins.tolist()`; Tests L94–95/108 assert floats. A global tensor return would corrupt the margins pipeline and 3 tests. Rejection stands.
- **Option B minimal blast radius confirmed.** Only `compute_live_rho_c` switches to `forward_logits_tensor`; `forward_margin`/`forward_logits` (float) are untouched; `ensure_readout_class_patch` is untouched (and intentionally does not wrap the tensor path, which is correct — the graph must survive).
- **Mathematical value preserved.** §6 shows both paths compute `w·h + b` in float64; equivalence within float64 rounding. The remediation adds the graph; it does not redefine `rho_c`/`sigma_c` (§6, §8). Consistent with "restore the missing contract, not redefine the metric."
- **No silent-corruption path.** §4.1/§7 T4 explicitly forbid `.detach()`, `torch.tensor(scalar)`, `[value]`, or `requires_grad=True` on constants — directly addresses the warned-against `g_R` corruption.

## C. Findings / Recommended Hardening (non-blocking)

1. **Add an explicit guard inside `forward_margin_tensor`.** The spec (§5) states non-tensor/shape-mismatch SHOULD raise `PreflightError`, but §4.1 does not yet show the guard. Recommend adding at the top of `forward_margin_tensor`:
   ```python
   import torch
   if not isinstance(hL, torch.Tensor) or hL.dim() != 1 or int(hL.shape[0]) != len(self.w):
       raise PreflightError("forward_margin_tensor: hL must be 1-D torch.Tensor of length len(w)")
   ```
   This mirrors the defensive style of `compute_readout_total_alignment` (Test F) and prevents a malformed `hL` from producing a misleading value or a different failure mode. **Recommendation: adopt in implementation.**

2. **Test D fake must be extended.** Existing Test D's `_FakeReadout.forward_logits` (L358–359) returns tensors and currently masks the bug. After the fix, `compute_live_rho_c` calls `forward_logits_tensor`, so `_FakeReadout` MUST implement `forward_logits_tensor` (or the test will `AttributeError`). The spec (§7 T7) requires a REAL-`Readout` regression test; the implementation plan must also update the Test D fake to supply `forward_logits_tensor`. **Recommendation: record in implementation plan.**

3. **Mixed-precision gradient note (informational, not a blocker).** `hL.double()` makes the forward `s` float64, matching the existing NumPy float64 readout. Autograd will return `grad(s, lora_params)` in the LoRA params' dtype (float32). This is a genuine gradient and consistent with the protocol's actual numeric practice (the frozen `psdg_fn` also differentiates a float32 model forward). No action required; documented here so the implementation/tests do not mistakenly expect float64 gradients.
