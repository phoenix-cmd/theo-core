## 1. Defect (recap)

`compute_live_rho_c` computes the readout-only decision gradient `g_R = alpha_c * grad_{lora_params}(s)`, where `s` is the readout decision logit `z_PRO` at the decision position. `s` MUST be an autograd-connected torch scalar so `torch.autograd.grad(s, lora_params)` is defined.

Currently `s = z_pro` (L705) where `z_pro = float(probs[PRO_ID].item())` (L712) ← `z_pro, z_abs = readout.forward_logits(hL)` (L704) ← `forward_logits` returns `(float, float)` because `forward_margin` returns `float(np.asarray(w) @ np.asarray(h) + b)` (L183). The readout logit is detached into a Python `float`, so `grad(float, lora_params)` raises `TypeError: 'float' object is not iterable` at L724.

This is an **autograd return-contract mismatch**, not a numerical or scientific error in the readout forward value.

## 3. Design Options

### Option A — Change existing `forward_margin`/`forward_logits` globally to return tensors.  **REJECTED.**
- Would break `compute_decision_margin_and_metrics` (L519/535): `np.array([tensor,...])` → object array; `margins[:8] > 0` and `margins.tolist()` fail; Stage 8 margins consumption breaks.
- Would break Tests L94–95, L108 (assert floats).
- Unnecessary semantic blast radius across Stage 5 margins, Stage 8, and 3 tests. Per directive: **not authorized.**

### Option B — Add a dedicated graph-preserving tensor path; keep `forward_margin`/`forward_logits` unchanged.  **SELECTED (recommended).**
- Minimal blast radius: 1 new caller (`compute_live_rho_c`), plus the two new methods. All existing scalar/NumPy consumers and Stage 5/Stage 8 semantics untouched.
- The bug is fixed by **adding the missing interface**, not by changing a mature one.

## 4. Recommended Design (Option B)

### 4.1 New method `Readout.forward_margin_tensor`
```python
def forward_margin_tensor(self, hL: "torch.Tensor") -> "torch.Tensor":
    """Graph-preserving readout decision margin for autograd consumers (compute_live_rho_c only).

    hL: 1-D torch.Tensor, shape (D,), on the model device, MUST be connected to the
        computation graph (requires_grad via the model). MUST NOT be detached.
    Returns: scalar torch.Tensor (float64) = w·hL + b, mathematically identical to
        forward_margin(numpy) but carries the autograd graph so grad(., lora_params) is valid.
    """
    import torch
    w_t = torch.as_tensor(self.w, dtype=torch.float64, device=hL.device)   # (D,) float64, requires_grad=False
    b_t = torch.as_tensor(float(self.b), dtype=torch.float64, device=hL.device)  # () float64
    return torch.matmul(w_t, hL.double()) + b_t   # float64 scalar; graph flows through hL.double()
```

### 4.2 New method `Readout.forward_logits_tensor`
```python
def forward_logits_tensor(self, hL: "torch.Tensor"):
    s = self.forward_margin_tensor(hL)
    return s, -s   # (z_PRO_t, z_abs_t), both graph-connected torch scalars
```

### 4.3 Caller change (only one)
In `compute_live_rho_c` (L704):
```python
# BEFORE: z_pro, z_abs = readout.forward_logits(hL)      # returns detached floats -> L724 crash
# AFTER:
z_pro, z_abs = readout.forward_logits_tensor(hL)          # graph-connected tensors
```
`s = z_pro` (L705) then remains a graph-connected tensor; `torch.autograd.grad(s, lora_params, allow_unused=True, ...)` (L724) is valid. All subsequent logic (alpha_c, g_R, rho_i, rho_c, sigma_c) unchanged.

### 4.4 Patch interaction
`ensure_readout_class_patch` (L193–207) wraps `forward_logits` only. `forward_logits_tensor` is a separate attribute and is intentionally NOT wrapped — the tensor path must keep the graph (no detach). No change to the patch.

## 6. Numerical Equivalence Proof (forward value preserved; graph added)

For the **identical** `hL` (torch tensor, shape (D,)):
- Existing: `forward_logits(hL)` → `forward_margin(hL)` = `float(np.asarray(w,float64) @ np.asarray(hL,float64)) + b`. Computed in float64; `hL` detached to NumPy.
- New: `forward_logits_tensor(hL)` → `forward_margin_tensor(hL)` = `torch.matmul(w_t, hL.double()) + b_t`. Computed in float64; `hL.double()` keeps the graph.

Both evaluate `w·h + b` in float64. The dot product of two float64 vectors is identical under NumPy and PyTorch BLAS to within float64 rounding (≤ 1e-12 relative). Therefore:
- `forward_logits_tensor(hL)[0].item()` ≈ `forward_logits(hL)[0]` within a tight tolerance.
- `forward_logits_tensor(hL)[1].item()` ≈ `-forward_logits(hL)[0]` (i.e., equals `forward_logits(hL)[1]`).
- The new path ADDS the autograd graph; it does NOT alter the scalar value. `g_R = alpha_c * grad(s, lora_params)` becomes a genuine gradient (was undefined). `rho_c = mean_i rho_i`, `sigma_c = mean_i (rho_i**2)` are unchanged in formula and now computable.

This remediation restores the missing contract; it does **not** redefine the metric.

## 7. Test Plan (acceptance tests)

All tests MUST use the **real `Readout` class** (or a float-returning stand-in) to exercise the actual contract — the existing Test D fake (L358–359) returns tensors and therefore **masks** the bug.

- **T1 — numerical equivalence (the critical acceptance test).** For an identical graph-connected `hL`, assert `forward_logits_tensor(hL)[0].item()` and `forward_logits_tensor(hL)[1].item()` match `forward_logits(hL)[0]`/`[1]` (existing floats) within `1e-9`. Protects against "fixing autograd while subtly changing the science."
- **T2 — graph connectivity.** Assert `z_PRO.requires_grad is True` and `z_PRO.grad_fn is not None`; assert `z_PRO.is_leaf is False` (not a detached constant). Assert `torch.autograd.grad(z_PRO, hL, ...)` is non-None (connected to input).
- **T3 — intended gradients (FULL REAL AUTOGRAD CONTRACT).** With a **real PEFT LoRA model** whose hidden state genuinely depends on `lora_params`, assert `g = torch.autograd.grad(z_PRO, lora_params, allow_unused=True)` returns a tuple of length `len(lora_params)`; `g` is **not entirely `None`** (graph reaches the actual LoRA computation, not merely `hL` in isolation); participating params yield **finite, NON-ZERO, shape-matching** gradients (genuine participation — not all-zero/all-`None`); only truly unused params may be `None`.
- **T3b — `g_R` must not be silently degenerated.** The assembled per-sample `g_R` (`flat_s` after `alpha_c * grad`) must be a non-degenerate, non-all-zero vector for participating params; `rho_i` must be a genuine cosine in `[-1, 1]`, not forced to 0.0/±1.0 by a disconnected/zero graph; `per_sample_rho` not all exactly `0.0`.
- **T4 — no detached-tensor workaround.** Assert the implementation contains NO `.detach()` on the readout path and that `z_PRO` is genuinely graph-connected (covered by T2); a sensitivity check: perturbing an upstream embedding changes `z_PRO`. Reject any design using `torch.tensor(scalar)`, `[value]`, or `requires_grad=True` on a constant.
- **T5 — zero/unused gradients per protocol.** With a synthetic model containing an unused param, assert `compute_live_rho_c` yields a **zero vector** (`zeros_like(p)`) for that param (existing protocol L727–728), never `None` leaking into `torch.cat`.
- **T6 — Stage 5 unchanged.** Stage 5 (`compute_live_cos_H1`, B0 anchor) does NOT call `compute_live_rho_c` or the new methods; assert the existing Stage 5 exact-reproduction test (6E.20.4 Test A) still passes and that `forward_margin`/`forward_logits` (float) are byte-for-byte unchanged in contract.
- **T7 — Stage 6 no longer fails on type contract (FAIL-BEFORE / PASS-AFTER).** Call `compute_live_rho_c` through the **real `Readout`** (float-returning `forward_logits`) with the new `forward_logits_tensor` path; assert it returns `(rho_c, sigma_c, per_sample_rho)` with **no `TypeError`**, all finite, `sigma_c == mean(rho_i**2)` (§5.7), and `rho_c`/`per_sample_rho` genuine cosines in `[-1, 1]` (non-degenerate per T3b). This is the regression test that **FAILS on current code** (raises `TypeError` at L724) and **PASSES after fix**; verify by running the suite against the unmodified runner (expect failure) then the fixed runner (expect pass).
- **T8 — rho_c is a genuine cosine.** Assert `rho_c` and all `per_sample_rho` lie in `[-1, 1]` (not analytically forced), confirming the scientific quantity is intact.
