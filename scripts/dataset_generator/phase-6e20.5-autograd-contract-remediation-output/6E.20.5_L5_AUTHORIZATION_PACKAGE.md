## 4. Evidence for the Requested Change

Root cause (confirmed in `6E.20.4_STAGE6_DIAGNOSTIC_REPORT.md`): at `run_phase_6e20_reevaluation.py:724`, `torch.autograd.grad(s, lora_params)` receives `s` as a **detached Python float** because `forward_logits`→`forward_margin` returns `float(np.asarray(w) @ np.asarray(h) + b)`. `grad(float, ...)` raises `TypeError: 'float' object is not iterable`. The defect was masked in 6E.20.2/6E.20.3 because Stage 5 previously HALT'd before Stage 6; 6E.20.4's Stage 5 fix exposed it.

Option A (global tensor return) was **rejected**: the caller map proves `forward_margin` is consumed by `compute_decision_margin_and_metrics` (NumPy scalar path, L519/535), Stage 8 margins, and 3 float-asserting tests — a global change has unnecessary blast radius. Option B (dedicated tensor path) is the smallest-semantic-blast-radius design: 1 new caller + 2 new methods; all scalar consumers and Stage 5/Stage 8 semantics untouched.

The fix **restores the missing autograd contract**; it does **not** redefine the readout forward value (proven numerically equivalent in float64, §6 of the spec) and does **not** alter `rho_c`/`sigma_c`.

## 7. Reviewer Endorsement (carried forward)

The dedicated tensor path is the correct scientific response: it supplies the missing interface (`s` as an autograd-connected torch scalar) without altering the mature float/NumPy `Readout` contract that multiple downstream consumers depend on. The key invariants to preserve exactly:

- `forward_margin_tensor` computes `w·h + b` in float64, **mathematically identical** to `forward_margin`; it only ADDS the autograd graph.
- `compute_live_rho_c`'s `g_R = alpha_c * grad_{lora_params}(s)` becomes a genuine gradient (was undefined). `rho_c`/`sigma_c` formulas are unchanged.
- `hL` must remain graph-connected (no `.detach()`); `w_t`,`b_t` are `requires_grad=False` constants.

This remediates the Stage 6 contract defect while leaving every frozen constraint intact.
