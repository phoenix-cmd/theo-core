# 6E.20.7 — Implementation Plan (Telemetry-Only)

**Status:** PLAN ONLY. Not authorized for execution. No code in this phase.
**Principle:** Add data persistence/telemetry and analysis only. No protocol-rule changes. No change to the runner's decision logic beyond *capturing* what `psdg_fn` / `crgc_fn` already compute. No modification of frozen 6E.18 machinery, `collect_nepr.py`, thresholds, formulas, or 6E.20.5 results.

## 1. What already exists (reuse, do not reimplement)
- `psdg_fn(model, readout, item, lora_params, tokenizer)` returns `g_total` (PSDG total gradient over `lora_params`). Frozen.
- `crgc_fn(g_pos, g_abs)` returns `cos_H1_aggregate`. Frozen.
- `compute_readout_total_alignment(...)` returns per-sample `rho_c`, `sigma_c`, and the component vectors (includes `g_total`, `g_R`). Frozen.
- `reevaluation_runs.json` already persists `cos_H1`, `rho_c`, `sigma_c`, `cohens_d`, `balanced_accuracy`, `margins[16]` — but NOT the raw gradient vectors/norms or per-sample decompositions. **This is the gap.**

## 2. Changes (telemetry-only additions)
### 2.1 Gradient capture (inside existing `psdg_fn` call sites, no logic change)
- After each `g_total = psdg_fn(...)` and each `g_R = ...`, persist:
  - `g_total_norm = ||g_total||`, `g_R_norm = ||g_R||` (per sample × condition × checkpoint).
  - Per-sample `cos_H1_i` = `compute_cosine_similarity(g_pos_i, g_abs_i)` (sample-level, not mean-then-cosine).
  - Per-sample `rho_i` (already computed by `crgc_fn`; persist the per-sample value, not only the mean).
- Store vectors via reference/hash to avoid 7×4×16×8 huge dumps; keep norms + a sample-keyed vector cache file outside `reevaluation_runs.json`.

### 2.2 Cross-condition decomposition (post-hoc, no new gradient computation)
- `g_total_common[cond,ckpt] = mean over both framings of g_total`.
- `g_total_specific[cond,ckpt] = mean(PRO g_total) − mean(ABS g_total)` = the framing-unique component.
- `pos_mean_norm`, `abs_mean_norm` persisted (Q5.3 constant-check).

### 2.3 Sensitivity control — SENS (non-degenerate, pre-registered)
- Build a held-out `SENS` probe set of N samples (N fixed before run) using **genuinely distinct** paraphrase framings of the **same** verdict (e.g., *The statement is true* vs *The statement is not false*). No gradient copying between framings.
- For each SENS sample, compute `g_total` for both framings via the **real frozen `psdg_fn`**; aggregate with the frozen `compute_raw_gradient_cosine` (mean-of-gradients then cosine) — identical path to the experimental conditions. No new aggregation rule.
- Pre-registered expectation: `cos_H1(SENS) >= 0.95`. Pre-registered failure action: if `< 0.95`, mark the observable invalid (per spec Section 4); do NOT feed SENS into H1/P1–P6.
- Gated OFF by default; enabled only by explicit authorization. SENS is diagnostic only.

### 2.4 Four-cause classification (implements spec Section 3b)
- From persisted telemetry compute `C_common`, `C_spec`, `r_cs`, `V_het`, `agg` per (condition, checkpoint).
- Apply the pre-registered floors: `FLOOR_r_cs = 0.20`, `FLOOR_Cspec_abs = 1e-3 * median(C_common over S4,S8)`, `FLOOR_Vhet = 0.25`, `FLOOR_Vhet_stable = 0.10`, `SENS_EXPECT = 0.95`. The floor *formulas* are fixed in the spec before data; only the run-time medians are computed at execution.
- Emit per-criterion pass/fail + exceedance magnitude; apply tie/overlap handling (report all triggered flags; primary = largest exceedance ratio). No tuning to data.
- Output: append a classification table to `6E.20.7_TELEMETRY_ANALYSIS.md`. Diagnostic only — never written into `evaluate_protocol_hypotheses`.
