# 6E.20.4 — Independent Specification Audit

- **Audits:** `6E.20.4_SPECIFICATION.md`
- **Auditor stance:** adversarial / independent; challenge the spec before any code is written.
- **Verdict:** **PASS WITH TWO MINOR CAVEATS** (both resolvable in the implementation plan; neither blocks progression).

---

## A. Does the spec address the confirmed root cause?

Root cause (confirmed): `compute_live_cos_H1` runs with the PEFT model in `train()` mode, so `LORA_DROPOUT=0.05` is active, injecting ~`1e-3` variance into `cos(H1)`; the anchor `0.428355` was generated with dropout off.

Spec §4.2 inserts `peft_model.eval()` immediately before the `compute_live_cos_H1` call and restores afterward. This directly disables dropout for the B0 computation and matches the anchor's regime. **Correct and minimal.** ✓

---

## B. Is the scope truly minimal?

- The guard wraps only the `compute_live_cos_H1` invocation inside `run_stage5_b0_historical_reproducibility_anchor` (`:768`). It does not touch Stage 6/7 margin metrics, NEPR, or any other stage. ✓
- §3 explicitly forbids a global `model.eval()`. ✓
- The change is purely a regime guard; it does not alter any formula. ✓

**Caveat 1 (clarity):** The spec should explicitly state that `peft_model.eval()` must be applied to the *same object* that is passed into `compute_live_cos_H1` (the `peft_model` parameter of `run_stage5_b0_historical_reproducibility_anchor`), not a copy or the unwrapped `base_model`. The implementation plan must pin this. (Resolved below in §C of the plan.)

---

## C. Hard-constraint conformance

All listed prohibitions (§5) are preserved by the proposed change:
- Tolerance `1e-4` unchanged — the guard does not touch `B0_REPRODUCIBILITY_TOLERANCE`. ✓
- Anchor `0.428355` unchanged — never referenced for modification. ✓
- No averaging / best-of / correction factor / anchor recomputation. ✓
- P1–P6, `evaluate_protocol_hypotheses`, joint gate, outcome matrix — untouched. ✓
- Frozen 6E.18 machinery, NEPR, 6E.20.1/6E.20.2 — untouched. ✓

The rejected alternative (recompute anchor / widen tolerance) is correctly excluded and its rationale is sound: the evidence shows the anchor reproduces exactly under eval mode, so the regime — not the anchor — is what must move. ✓

---

## D. Safeguard sufficiency

§6 requires: capture mode, `eval()`, verify `training is False`, compute, restore in `finally`, verify restoration, exception-safe. All present in §4.2 pseudocode. The `try/finally` guarantees restoration even on exception (covers Test F). ✓

**Caveat 2 (edge):** If `compute_live_cos_H1` itself flips the mode internally (e.g., calls `model.train()`), the post-restore assertion would catch it. The spec should note that the implementation plan should confirm `compute_live_cos_H1` does not mutate mode — it only calls `ensure_readout_class_patch()` (verified during the diagnostic phase; it does not alter `training`). This is already known; recording it in the plan is sufficient.

---

## E. Test coverage adequacy

Tests A–H map cleanly to the safeguards and constraints. Particularly strong:
- Test C/E verify the guard engages and preserves prior mode (the core fix).
- Test F verifies exception safety (the `finally` path).
- Test G verifies scope isolation (no spillover to Stage 6).
- Test H guards against accidental scientific-logic drift.

One addition suggested (non-blocking): a test that the B0 recomputed value under the guard equals the historical anchor for **all four** anchor checkpoints `{4,6,14,15}`, not only step-4, since A currently names only step-4. The implementation plan may broaden A to all four keys.

---

## F. Reproducibility / determinism risk

Eval mode on the same CUDA device reproduced `0.428355` bit-identically across 3 processes during the diagnostic phase. Disabling dropout removes the only observed source of run-to-run variance in this path; GPU nondeterminism was already ruled out. The repair therefore restores determinism. ✓

---

## G. Audit conclusion

The specification is correct, minimal, constraint-preserving, and safe. Proceed to the implementation plan. Resolve Caveats 1 and 2 in the plan; optionally broaden Test A to all four anchor checkpoints.

**Auditor disposition: PASS — proceed to implementation plan.**
