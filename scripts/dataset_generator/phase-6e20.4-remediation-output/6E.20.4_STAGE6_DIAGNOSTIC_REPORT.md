# 6E.20.4 — Stage 6 `'float' object is not iterable` Diagnostic Report

**Status:** DIAGNOSTIC-ONLY. No source or execution artifact was modified. No production fix applied.
**Scope:** New, separately scoped defect exposed after 6E.20.4 successfully cleared Stage 5 (B0 reproducibility gate).
**Date:** 2026-08-21

---

## 1. Summary

The 6E.20.4 remediation achieved its defined objective: the Stage 5 B0 reproducibility anchor gate now passes with Δ = 0.0 for all four historical checkpoints. Because Stage 5 no longer HALTs, the pipeline proceeds into Stage 6, where it terminates on an unhandled exception:

```
EXECUTION HALT: 'float' object is not iterable
```

A minimal, isolated diagnostic harness (no runner source edits; writes only to a temp dir) reproduced the exact failure and captured the **complete Python traceback** (Section 2). The defect is a **return-contract violation** at the `torch.autograd.grad` call inside `compute_live_rho_c`: the readout scalar `s` is a detached Python `float`, but the autograd API requires a tensor (or iterable of tensors).

## 4. Backward Type Trace (where the type diverges)

The `s` value is traced backward to where its actual type diverges from the type `compute_live_rho_c` expects:

1. `run_phase_6e20_reevaluation.py:724` — `s` passed to `torch.autograd.grad` as `outputs`. **Expected:** autograd-connected torch scalar (so `grad(s, lora_params)` yields the readout-only decision gradient `g_R`). **Actual:** Python `float`.
2. `run_phase_6e20_reevaluation.py:705` — `s = z_pro`.
3. `run_phase_6e20_reevaluation.py:712` — `z_pro = float(probs[PRO_ID].item())`. **Here `s` becomes a detached Python `float`** (`.item()` strips the tensor + autograd graph).
4. `run_phase_6e20_reevaluation.py:704` — `z_pro, z_abs = readout.forward_logits(hL)`.
5. `run_phase_6e20_reevaluation.py:186` — `forward_logits` returns `s, -s` where `s = self.forward_margin(h)`.
6. `run_phase_6e20_reevaluation.py:183` — `forward_margin` returns `float(np.asarray(self.w) @ np.asarray(h) + self.b)`. **Pure NumPy → detached Python `float`, no torch graph.**

**Divergence point:** `Readout.forward_margin` (line 183) returns a detached NumPy-derived `float`. The intended contract at the `torch.autograd.grad` boundary (line 724) requires `s` to be a torch scalar that is connected through `hL` (a model-hidden-state tensor) back to `lora_params`, so that `g_R = alpha_c * grad_{lora_params}(s)` is a genuine gradient of the readout decision logit w.r.t. the LoRA parameters.

## 5. Intended vs. Actual Type at the Boundary

- **Intended (per `compute_live_rho_c` docstring, Protocol v3.1 §5.7):** `s_i = readout scalar output z_PRO at the decision position` — a torch tensor on the autograd graph; `g_R_i = alpha_c * grad_{lora_params}(s_i)` is the readout-only decision gradient, later cosine-aligned with the total gradient `g_total_i` via the frozen `compute_readout_total_alignment`.
- **Actual:** `s` is a detached Python `float`. `grad(float, lora_params)` is undefined → crash. Even if "fixed" by wrapping (e.g., `s = [s]` or `torch.tensor(s)` with no graph), the gradient would be `None`/zero, **silently destroying the scientific computation of `g_R` and therefore `rho_c`/`sigma_c`.** This is precisely the class of patch that must be avoided.

## 6. Cause Classification

**Primary cause: incorrect return contract** (interface mismatch) between `Readout.forward_margin`/`forward_logits` and `compute_live_rho_c`.

Secondary attributes:
- **Latent contract violation** — the `Readout` forward path was written to return detached floats, incompatible with the tensor contract the Stage 6 rho_c path relies on.
- **Stage 6-only code path** — only `compute_live_rho_c` (invoked solely by Stage 6) requires the tensor contract. Stage 5's `compute_live_cos_H1` does NOT call `compute_live_rho_c`; it uses the frozen `crgc_fn`/`psdg_fn`, which build their own autograd graphs and are unaffected. (Confirmed: `compute_live_cos_H1` returned `0.423098` for B0/checkpoint_4 in the isolated reproduction, i.e., Stage 5 material is sound.)
- **Not** a checkpoint/readout-specific data-shape issue (reproduced for B0/checkpoint_4, the first Stage 6 evaluation), and **not** an outdated caller/callee interface between frozen modules (the frozen `psdg_fn`/`crgc_fn` are not involved here).

## 7. Comparison Against Frozen / Intended Interface

- **Frozen 6E.18 machinery** (`per_sample_decision_gradient`, `compute_raw_gradient_cosine`): NOT implicated. These feed `compute_live_cos_H1` (Stage 5) and `compute_live_rho_c`'s `g_total` only; they are correct and untouched.

The intended protocol interface requires a torch tensor so gradients flow from the readout logit through `hL` to `lora_params`. The current implementation does not satisfy that contract.
- **Scientific logic preserved:** No scientific logic was modified during diagnosis. The intended `rho_c = mean_i rho_i` / `sigma_c = mean_i (rho_i**2)` (§5.7) remains defined; it is merely unreachable due to the contract bug.

## 9. Proposed Minimal Remediation Scope (NOT implemented — for separate review/authorization)

**Goal:** make `s` an autograd-connected torch scalar so `grad_{lora_params}(s)` is a genuine readout-only decision gradient, without weakening or redefining the `rho_c`/`sigma_c` science.

**Minimal, contract-correct fix (illustrative, not applied):**
- Change `Readout.forward_margin` / `forward_logits` to return **torch tensors** computed via torch ops on `hL` (a torch tensor from the model) using the readout weights `w`, `b` as torch constants, e.g. `s = (w_t @ hL_t + b_t)` where `w_t, b_t` are `torch.tensor(..., requires_grad=False)` and `hL_t` carries the model graph. Then `s = z_pro` (line 705) is a graph-connected tensor and `torch.autograd.grad(s, lora_params)` yields `g_R` correctly.
- This confines the change to the runner's `Readout` forward path + `compute_live_rho_c`'s use of `s`; it does **not** touch Stage 5, the frozen 6E.18 machinery, `collect_nepr.py`, `evaluate_protocol_hypotheses`, the joint gate, or any threshold/anchor.

**Explicitly forbidden shortcut (do NOT apply):** wrapping `s` in a list, or `torch.tensor(s)` without a graph, or any change that makes the exception disappear while producing `None`/zero gradients. That would silently corrupt `g_R → rho_c → sigma_c` and violate the tightly-controlled protocol.

**Re-authorization requirement:** any source change invalidates the bound runner hash `540874237…` and MUST restart the audit → hash → L5 review → execution-authorization chain before re-execution.
