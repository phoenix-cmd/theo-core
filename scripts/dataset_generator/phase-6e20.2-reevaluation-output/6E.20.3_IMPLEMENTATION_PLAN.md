### 3.2 Schema Versioning (Revised)

Format: `MAJOR.MINOR.PATCH` (semantic versioning).

| Component | Rule |
|-----------|------|
| MAJOR | Breaking change: new mandatory fields, removed fields, structural reorganization. Incompatible across MAJOR versions. |
| MINOR | Backward-compatible addition: new optional fields. Same MAJOR readers can read newer MINOR. |
| PATCH | Documentation, internal reorganization with no schema change. |

**Validation rules:**
1. Format check: must match `^\d+\.\d+\.\d+$`.
2. MAJOR check at load time: `int(version.split('.')[0])` must equal `1`.
   - Mismatch: ENVIRONMENT_UNVERIFIABLE.
3. MINOR check: informational only. Same MAJOR, different MINOR: proceed with intersection of defined fields.
4. PATCH: ignored for comparison.

**Missing required field rule (critical):**
A required field that is absent in either NEPR (even within compatible MINOR versions)
-> ENVIRONMENT_UNVERIFIABLE. Fields are NOT synthesized as null, 'unknown', or any
other default. The absence of a field is distinct from the field being present with
the value 'unknown'. Schema evolution must not manufacture false SAME_ENVIRONMENT
by silently equating absent fields with defaults.

## Section 4: Canonical Hashing Implementation

### 4.1 compute_nepr_hash(nepr_dict: dict) -> str

```python
def compute_nepr_hash(nepr_dict: dict) -> str:
    import hashlib, json
    d = dict(nepr_dict)
    d.pop("nepr_hash", None)
    canonical = json.dumps(d, sort_keys=True, separators=(',', ':'),
                           ensure_ascii=True, default=str)
    return "sha256:" + hashlib.sha256(canonical.encode("utf-8")).hexdigest()
```

### 4.2 Canonical JSON Rules

- Key sort: Alphabetical by full dotted path.
- Separator: Compact (',', ':') -- no spaces.
- Strings: UTF-8, ensure_ascii=True (all non-ASCII escaped).
- Floats: Python default repr() (not truncated, not rounded).
- Integers: Standard JSON integer serialization.
- Booleans: Lowercase true/false (JSON default).
- Null: null (JSON default).
- Lists: Element order preserved.

### 4.3 Properties

- Deterministic: same input yields same hash.
- Tamper-evident: any field change yields different hash.
- nepr_hash excluded from its own computation (self-referential exclusion).

## Section 5: NEPR Storage and Manifest Binding (Revised)

### 5.1 Artifact Chain Design

The pre-execution manifest is IMMUTABLE once created. A separate binding artifact
links the NEPR to the execution. Three distinct artifacts:

| Artifact | Created | Modified | Purpose |
|----------|---------|----------|---------|
| pre_execution_sha256_manifest.json | Stage 1 (before model load) | NEVER | Immutable record of all frozen inputs before execution |
| numerical_environment_provenance.json | POST-LOAD (after model init) | NEVER | Runtime environment snapshot |
| execution_environment_binding.json | POST-NEPR (after NEPR emission) | NEVER | Binds NEPR hash to artifact hashes; establishes temporal chain |

### 5.2 pre_execution_sha256_manifest.json (Immutability Preserved)

Written once at Stage 1. NEVER rewritten. Same structure as current 6E.20.2 manifest:

```json

  "timestamp_utc": "2026-08-18T00:00:00Z",
  "phase": "6E.20.3",
  "files": { "... existing entries ..." }
}
```

No numerical_environment_provenance key. This manifest is a pure pre-execution record.

## Section 6: Atomic-Write and Post-Write Verification (Revised)

### 6.1 Atomic Write Protocol

```python
def atomic_write_json(path: Path, data: dict) -> None:
    import json, os
    tmp_path = path.with_suffix(path.suffix + '.tmp')
    tmp_path.write_text(json.dumps(data, indent=2, default=str), encoding='utf-8')
    # os.replace is atomic on POSIX and as-close-to-atomic-as-possible on Windows.
    # Unlike unlink+rename, it does not create a window where the destination is absent.
    os.replace(tmp_path, path)
```

Key difference from prior revision: uses os.replace() instead of unlink()+rename().
os.replace() is the correct POSIX atomic replacement operation and avoids the window
where the destination file does not exist.

### 6.2 Post-Write Verification

For NEPR specifically, after atomic_write_json:
1. Re-read the written file.
2. Re-compute nepr_hash from the re-read content.
3. Compare to the nepr_hash field in the written content.
4. Mismatch: RuntimeError (halt, do not proceed).

For binding and manifest files, re-read and verify SHA-256 matches expected.

### 6.3 Failure Semantics

- If os.replace fails: tmp_path remains for debugging, original path unchanged.
- If post-write verification fails: RuntimeError raised, tmp_path cleaned up.
- All NEPR artifacts are write-once; if they exist at the expected path, the
  implementation must raise an error rather than silently overwriting.---

## Section 7: Deterministic Environment Comparison (Revised)

### 7.1 Comparison Function

```python
def compare_nepr(current: dict, reference: dict) -> dict:
    """Compare two NEPR records deterministically.

    Returns:
    - classification: "SAME_ENVIRONMENT" | "CROSS_ENVIRONMENT" | "ENVIRONMENT_UNVERIFIABLE"
    - category_results: {A: bool, B: bool, C: bool, D: informational, E: bool, F: informational}
    - field_details: {field_name: {current, reference, equal, category, informational}}
    - disclaimers: list[str]
    - comparison_timestamp_utc: str
    - current_nepr_hash: str
    - reference_nepr_hash: str
    """
```

### 7.2 Five-Step Algorithm

**Step 1: Schema compatibility check**
- If current.nepr_schema_version MAJOR != reference.nepr_schema_version MAJOR:
  -> ENVIRONMENT_UNVERIFIABLE, reason: "MAJOR schema version mismatch".
- If either nepr_schema_version is missing:
  -> ENVIRONMENT_UNVERIFIABLE, reason: "Legacy NEPR: missing nepr_schema_version".

**Step 2: Artifact binding check**
- For each field in category_E_artifact_binding:
  if current[field] != reference[field]:
    -> ENVIRONMENT_UNVERIFIABLE, reason: "Artifact binding mismatch: {field}".

**Step 3: Software + Hardware + Numerical equality**
- For each category in [A, B, C]:
  For each field in category:
    - Required field absent in either NEPR -> ENVIRONMENT_UNVERIFIABLE (NOT synthesized null/unknown).
    - list fields: element-wise equality after length check.
    - int/bool fields: exact ==.
    - string fields: exact ==.
    - dict fields (e.g., lora_dtype_detail): exact == on keys and values.
    - If any field differs: -> CROSS_ENVIRONMENT, reason: '{category}.{field} mismatch'.

**Step 4: Category D (informational only)**
- Record all Category D field differences for the report.
- Do NOT influence classification.

**Step 5: Emit report with disclaimer**
- If all A/B/C/E equal: classification = 'SAME_ENVIRONMENT'.
- Add disclaimer: "SAME_ENVIRONMENT does not imply SAME_EXECUTION_STATE.
  Category D (reproducibility state) differences may affect numerical reproducibility."

### 7.3 Structured Comparison Report

```json
{
  "classification": "SAME_ENVIRONMENT",
  "category_results": {
    "A_software": true,
    "B_hardware": true,
    "C_numerical": true,
    "D_reproducibility": "informational",
    "E_artifact_binding": true,
    "F_metadata": "informational"
  },
  "disclaimers": [
    "SAME_ENVIRONMENT does not imply SAME_EXECUTION_STATE. Category D differences may affect numerical reproducibility."
```

Written to: `<output_dir>/nepr_comparison_report.json`

### 8.2 model_parallel and device_map -- From Actual Execution Placement

These fields are NOT derived from gpu_count. They are set AFTER model load
and device placement by inspecting the actual model:

```python
import json

def _canonicalize_device_map(hf_device_map) -> str:
    """Canonicalize device_map to a deterministic string representation.

    Dict device maps are serialized as canonical JSON with sorted keys.
    This prevents false CROSS_ENVIRONMENT from insertion-order differences.
    """
    if isinstance(hf_device_map, dict):
        return json.dumps(hf_device_map, sort_keys=True, separators=(',', ':'))
    return str(hf_device_map)

def detect_execution_topology(model, gpu_count: int):
    """Detect actual model parallelism and device map from loaded model."""
    hf_device_map = getattr(model, 'hf_device_map', None)
    if hf_device_map is not None and hf_device_map:
        device_map = _canonicalize_device_map(hf_device_map)
        if isinstance(hf_device_map, dict):
            devices = set(v for v in hf_device_map.values() if isinstance(v, str))
            model_parallel = len(devices) > 1
        elif isinstance(hf_device_map, str) and hf_device_map != 'cpu':
            model_parallel = gpu_count > 1
        else:
            model_parallel = False
        return model_parallel, device_map
    if hasattr(model, 'module'):  # DataParallel/DDP wrapper
        return True, 'distributed'
    try:
        device = next(model.parameters()).device
        device_map = str(device)
    except StopIteration:
        device_map = 'cpu'
    return False, device_map
```

Key semantics:
- gpu_count=4, model on cuda:0 only -> model_parallel=False, device_map='cuda:0'
- gpu_count=4, model sharded via accelerate -> model_parallel=True, device_map='{"0":"cuda:0","1":"cuda:1"}' (canonical JSON)
- gpu_count=1, model on cuda:0 -> model_parallel=False, device_map='cuda:0'
- Dict insertion order does NOT affect the serialized representation (sorted keys).

### 8.3 lora_dtype -- Measured from Actual Parameters

The LoRA dtype is NEVER inferred from the base model dtype. It is measured by
inspecting actual adapter parameter dtypes after get_peft_model() and checkpoint loading:

```python
def measure_lora_dtype(peft_model):
    """Measure actual LoRA parameter dtypes from the loaded PEFT model."""
    from collections import Counter
    dtype_counter = Counter()
    total_params = 0
    for name, param in peft_model.named_parameters():
        if "lora_" in name:
            dtype_name = str(param.dtype).replace('torch.', '')
            dtype_counter[dtype_name] += 1
            total_params += 1
    if total_params == 0:
        return "unknown", {}
    detail = dict(dtype_counter)
    unique_dtypes = list(dtype_counter.keys())
    lora_dtype = unique_dtypes[0] if len(unique_dtypes) == 1 else "mixed"
    return lora_dtype, detail
```

The NEPR records the ACTUAL measured state:
- All LoRA params bf16 -> "bfloat16", {"bfloat16": N}
- Mixed dtypes -> "mixed", {"bfloat16": X, "float32": Y}
- No LoRA params found -> "unknown", {}

### 8.4 attention_backend -- Actual Selected Backend (Not Library Availability)

```python
def detect_attention_backend(model) -> str:
    """Detect the actual attention backend selected for this model.

    Hierarchy:
    1. Model config attn_implementation (explicitly configured)
    2. 'unknown' if resolution impossible

        attn_impl = getattr(config, 'attn_implementation', None)

                "flash_attention_2": "flash",
                "sdpa": "sdpa",
                "eager": "eager",
                "xformers": "xformers",
```

- config.attn_implementation == "sdpa" -> "sdpa" (verified selected)
- flash_attn installed but config says "sdpa" -> "sdpa" (installed != selected)

## Section 9: Schema Version Validation and Compatibility (Revised)

### 9.1 Schema Version Format

nepr_schema_version is a string "MAJOR.MINOR.PATCH" (e.g., "1.0.0", "2.1.3").

### 9.2 Validation Rules

1. Format check: must match `^\d+\.\d+\.\d+$`.
2. MAJOR version check: at load time, `int(version.split('.')[0])` must equal 1.
   - Mismatch: ENVIRONMENT_UNVERIFIABLE, reason: "NEPR schema MAJOR version X != expected 1".
3. MINOR check: informational only. Same MAJOR, different MINOR proceeds with
   intersection of defined fields.
4. PATCH: ignored for comparison.
5. Missing nepr_schema_version: ENVIRONMENT_UNVERIFIABLE, reason: "Legacy NEPR detected".

### 9.3 Required-Field Registry and MINOR-Version Compatibility (Revised)

Required fields are defined per-schema-version. Each NEPR schema version declares
which fields are REQUIRED and which are OPTIONAL. When comparing two NEPRs with
the same MAJOR but different MINOR versions:

1. Determine the INTERSECTION of defined fields across both schema versions.
2. Within this intersection, check only fields that are REQUIRED in BOTH schema
   versions. A field that is REQUIRED in v1.0.0 but optional in v1.1.0 is
   compared only if present in both NEPRs.
3. A field that does not exist in the older schema version's definition is
   NOT treated as missing-required. It is excluded from comparison.
4. A field that is REQUIRED in both versions but absent in one NEPR ->
   ENVIRONMENT_UNVERIFIABLE.

This means:
- v1.0.0 defines field X as required; v1.1.0 does not define field X at all:
  field X is excluded from comparison (it did not exist in v1.1.0's schema).
- v1.0.0 defines field X as required; v1.1.0 defines field X as optional:
  if present in both NEPRs, compare it; if absent in one, it is NOT
  treated as missing-required (it is optional in the newer schema).
- v1.0.0 defines field X as required; v1.1.0 defines field X as required:
  if absent in either NEPR -> ENVIRONMENT_UNVERIFIABLE.

For the initial v1.0.0 implementation, all fields in the schema are REQUIRED.
Future MINOR versions will explicitly mark new fields as OPTIONAL or REQUIRED
in their schema definition.

### 9.4 Compatibility Matrix

| Scenario | Behavior |
|----------|----------|
| Same MAJOR.MINOR.PATCH | Full exact comparison of all fields |
| Same MAJOR, different MINOR/PATCH | Compare intersection of defined fields; required fields in both versions must be present; fields defined only in one version are excluded from comparison |
| Different MAJOR | ENVIRONMENT_UNVERIFIABLE; comparison aborted |
| Missing nepr_schema_version | ENVIRONMENT_UNVERIFIABLE; legacy NEPR detected |
